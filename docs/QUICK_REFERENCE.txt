STEP-BY-STEP: IMPLEMENT WHOOP IN 30 MINUTES
================================================================================

1. REGISTER APP (5 min)
   └─ Go to https://developer-dashboard.whoop.com
   └─ Create Team → Create App
   └─ Copy: Client ID, Client Secret

2. SETUP BACKEND (15 min)
   └─ Add to .env:
      WHOOP_CLIENT_ID=xxx
      WHOOP_CLIENT_SECRET=xxx
   └─ Create POST /api/auth/whoop/login endpoint
      • Generate state parameter
      • Redirect to: https://api.prod.whoop.com/oauth/oauth2/auth
   └─ Create GET /api/auth/whoop/callback endpoint
      • Exchange code for token
      • Store token in database

3. TEST (10 min)
   └─ Click login, verify OAuth flow works
   └─ Call https://api.prod.whoop.com/api/v2/user/profile/basic
   └─ See user data come back ✅

COMMON MISTAKES (Don't Do These!)
================================================================================

❌ WHOOP
   • Forget state parameter → Add 8+ char random state
   • Use v1 API → Migrate to v2 before Oct 2025
   • Put secret in frontend → ALWAYS server-side only

❌ Fitbit
   • Forget PKCE → Always include code_verifier
   • Use HTTP → MUST be HTTPS only
   • Use iframe → Open dedicated browser

❌ Garmin
   • Expect free → Budget $5,000 per app
   • Try to pull data → It's push-based (webhooks)
   • Skip HMAC → Always verify webhook signatures

❌ Apple Health
   • Request all permissions → Ask per data type
   • Use simulator → Must use real iOS device
   • Forget privacy policy → App Store requirement

❌ Samsung Health
   • Use emulator → Only real Android devices
   • Use old SDK → Must migrate to new SDK
   • Expect all permissions → May need approval

SECURITY CHECKLIST
================================================================================

✅ DO:
   ☑ Store tokens encrypted at rest
   ☑ Use HTTPS for all requests
   ☑ Verify webhook signatures (Garmin)
   ☑ Use state parameter (prevents CSRF)
   ☑ Use PKCE for mobile apps
   ☑ Check token expiration
   ☑ Use refresh tokens

❌ DON'T:
   ☒ Store tokens in plain text
   ☒ Send tokens in URLs
   ☒ Use HTTP (always HTTPS)
   ☒ Trust unverified webhooks
   ☒ Store user passwords
   ☒ Commit credentials to git
   ☒ Log full access tokens

DATABASE TABLES YOU'LL NEED
================================================================================

user_providers table:
  - id (UUID)
  - user_id (FK to users)
  - provider_name (whoop, fitbit, etc.)
  - access_token (ENCRYPTED)
  - refresh_token (ENCRYPTED)
  - token_expires_at (timestamp)
  - is_primary (boolean)
  - is_connected (boolean)
  - connected_at (timestamp)
  - last_synced_at (timestamp)

health_metrics table:
  - id (UUID)
  - user_id (FK)
  - provider_name
  - metric_type (heart_rate, sleep, etc.)
  - metric_date (date)
  - metric_value (float)
  - unit (bpm, minutes, etc.)
  - synced_at (timestamp)

API ENDPOINTS YOU'LL CREATE
================================================================================

Authentication:
  POST   /api/auth/{provider}/login           # Start OAuth flow
  GET    /api/auth/{provider}/callback        # OAuth callback
  POST   /api/auth/{provider}/disconnect      # Revoke access

User Data:
  GET    /api/providers/{provider}/profile     # User info
  GET    /api/providers/{provider}/today       # Today's data
  GET    /api/providers/{provider}/date-range  # Historical data
  GET    /api/providers/{provider}/sync        # Force sync

Admin:
  GET    /api/providers/list                   # Connected providers
  GET    /api/providers/status                 # Sync status
  GET    /api/dashboard/metrics                # Aggregated data
