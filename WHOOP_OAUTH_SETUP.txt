================================================================================
WHOOP OAUTH SETUP GUIDE
================================================================================

This file explains how to set up WHOOP OAuth integration for your app.

================================================================================
STEP 1: GET WHOOP DEVELOPER CREDENTIALS
================================================================================

1. Go to: https://developer.whoop.com/dashboard
2. Log in or create a developer account
3. Create a new App
4. Copy these credentials and save them:
   - Client ID
   - Client Secret

================================================================================
STEP 2: REGISTER REDIRECT URI IN WHOOP DASHBOARD
================================================================================

IMPORTANT: This must match exactly what you put in your .env file!

For development:
  http://localhost:5001/api/oauth/whoop/callback

For production (replace with your actual domain):
  https://yourdomain.com/api/oauth/whoop/callback

In WHOOP Developer Dashboard:
  1. Go to your App settings
  2. Find "Redirect URIs" section
  3. Add: http://localhost:5001/api/oauth/whoop/callback

================================================================================
STEP 3: SET ENVIRONMENT VARIABLES
================================================================================

In your .env file, add/update:

WHOOP_CLIENT_ID=your_client_id_from_step_1
WHOOP_CLIENT_SECRET=your_client_secret_from_step_1
WHOOP_REDIRECT_URI=http://localhost:5001/api/oauth/whoop/callback

Example .env (complete):
---
WHOOP_CLIENT_ID=abc123xyz789
WHOOP_CLIENT_SECRET=secret_key_here
WHOOP_REDIRECT_URI=http://localhost:5001/api/oauth/whoop/callback
WHOOP_ACCESS_TOKEN=
WHOOP_REFRESH_TOKEN=
GEMINI_API_KEY=your_key
TWILIO_ACCOUNT_SID=your_sid
TWILIO_AUTH_TOKEN=your_token
TWILIO_PHONE_NUMBER=+1234567890
YOUR_PHONE_NUMBER=+1234567890
JWT_SECRET=your_secret_key
SUPABASE_URL=your_url
SUPABASE_ANON_KEY=your_key
SUPABASE_SERVICE_ROLE_KEY=your_key
---

================================================================================
STEP 4: CREATE OAUTH_STATES TABLE IN SUPABASE
================================================================================

Run this SQL in your Supabase SQL Editor:

File: supabase/migrations/create_oauth_states.sql

(This table is needed for CSRF protection and OAuth state management)

In Supabase:
  1. Go to your project
  2. Click "SQL Editor"
  3. Create a new query
  4. Copy all SQL from: supabase/migrations/create_oauth_states.sql
  5. Click "Run"

================================================================================
STEP 5: START YOUR APP
================================================================================

Terminal 1 - Start API server:
  $ PORT=5001 npm run api

Terminal 2 - Start frontend:
  $ npm run web:dev

================================================================================
STEP 6: TEST THE OAUTH FLOW
================================================================================

1. Open: http://localhost:5000/onboarding
2. Click "Connect WHOOP" button
3. You should be redirected to WHOOP login page
4. Log in with your WHOOP account
5. Grant permission for the app
6. You should be redirected back to your app

Expected result: WHOOP data should be connected to your account

================================================================================
TROUBLESHOOTING
================================================================================

Problem: "Invalid redirect URI" error from WHOOP
Solution:
  - Make sure WHOOP_REDIRECT_URI in .env matches EXACTLY what you registered
  - Check for typos, extra spaces, or wrong port numbers
  - Redirect URI is case-sensitive

Problem: OAuth callback page not found
Solution:
  - Make sure API server is running on port 5001
  - Check that /api/oauth/whoop/callback endpoint exists
  - Verify route is mounted in src/api/server.ts

Problem: "oauth_states table doesn't exist"
Solution:
  - Run the SQL migration in Supabase
  - Make sure SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY are correct

Problem: Tokens not being saved
Solution:
  - Check that user_health_providers table exists in Supabase
  - Make sure SUPABASE_SERVICE_ROLE_KEY is set (not anon key)
  - Check Supabase logs for database errors

================================================================================
API ENDPOINTS
================================================================================

POST /api/oauth/whoop/login
  - Initiates WHOOP OAuth flow
  - Returns: { success: true, auth_url: "https://..." }
  - Frontend redirects to auth_url

GET /api/oauth/whoop/callback
  - Handles OAuth callback from WHOOP
  - Receives: code and state parameters
  - Exchanges code for tokens
  - Stores tokens in database
  - Redirects back to app

================================================================================
CODE LOCATIONS
================================================================================

OAuth implementation:
  - Backend: src/api/oauth.ts
  - Frontend button: web/src/components/ConnectProviderButton.tsx
  - Config: src/config/index.ts
  - Database service: src/services/db/provider-service.ts

Database table:
  - user_health_providers: Stores connected providers and tokens

OAuth state table:
  - oauth_states: Stores CSRF protection state
